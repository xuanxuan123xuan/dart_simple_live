# TV 端基础能力实施记录

本轮面向 Android TV 和 TV Windows，按大屏观看价值补齐基础链路。手机、桌面主 App 继续承担账号登录和复杂数据维护；TV 提供播放、选房与同步接收。

## 实现范围

| 模块 | 本轮行为 |
| --- | --- |
| 抖音分类 | 递归保留三级及更深分类；同一路由逐级浏览、“全部”房间、返回和遥控器焦点恢复；旧请求不覆盖新分类 |
| 单房间控制 | 可聚焦的暂停、静音、音量、刷新和频道切换；用户暂停不会被重连、后台恢复或迟到的播放器操作覆盖 |
| 播放恢复 | 有限重试和线路切换；区分直播、确实下播和未知状态；连续两次确认下播后才按下播处理 |
| 网络波动 | 共用缓冲检测；起播热身、降质冷却和用户开关；暂停、后台期间不消耗降质预算 |
| 多屏 | 单窗口内 Android 默认 2 路、可选 4 路，Windows 最多 4 路；均分、主次、单格放大；每路独立操作；默认单路有声、可选混音 |
| 多屏资源 | 串行加载、异步代次保护、后台暂停、等待关闭后切换单路；反复收到内存压力时释放副路，用户可手动恢复 |
| 斗鱼 | 可选 Cookie 管理、前台自动续期、手动换号后重载；继续使用服务端实际返回的清晰度展示 |
| 小红书 | 第六个平台，通过直播链接、房间号、关注和历史进入；保留 hostId；公开 SSR 视频路径与可选 Cookie |
| 小红书 Android | 隐藏 WebView 仅处理已确认的五个 GET 只读端点；串行请求、超时取消、房间释放和一次签名重建 |
| 小红书 Windows | 继续使用视频路径，签名和弹幕能力明确降级；弹幕失败不会改变视频的直播状态 |
| 三种同步 | 局域网接收、远程房间、WebDAV 配置包覆盖斗鱼和小红书账号；保留既有 B 站、抖音和快手语义 |

选房入口覆盖首页、关注列表和单直播间；选择器支持关注、历史、搜索结果与直播链接。TV 不增加局域网发送端管理页面。

## 同步兼容约定

- 新配置包版本为 schema 4，账号统一存于 `accounts.items`。TV 接受 schema 2、3、4。
- 设置项不携带 Cookie。账号是否导入由账号选项单独控制；空账号不会隐式清除本地账号。
- TV 不导出不支持的标签和屏蔽预设，避免覆盖手机端数据；未知平台的关注、历史记录跳过。
- WebDAV 已找到新版配置包时，解析或导入错误直接报告失败；仅未找到新版包时允许读取旧文件。
- 远程新增账号使用 `accountType` 与 `credentials.cookie`，不把 Cookie 放在旧 B 站消息的顶层。
- 缺失账号类型兼容旧 B 站消息，非空未知类型拒绝处理。新账号广播前检查所有其他成员均为支持的 TV 1.8.0 或更新版本。
- 账号及配置包解析异常使用不含原文的错误提示，防止异常附带凭据片段。

## 本轮排除项

不移植聚合搜索、关注标签编辑或筛选、画中画、截图、完整聊天历史、低延迟追赶、独立进程多窗口，也不研究小红书目录和关键词搜索。
