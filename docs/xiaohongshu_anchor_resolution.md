# 小红书主播身份与跨场次解析

小红书直播链接中的房间号代表一场直播，不能作为主播的长期身份。本次修复把固定主播 ID 与当前场次房间号分开保存，覆盖小红书链接、本地关注和历史入口。

## 身份与状态

- 主播 ID 只接受 24 位十六进制字符串，来源限于当前直播间的主播字段、当前直播 deeplink 的 `host_id`，以及可信直播分享链接。
- 不从昵称、头像、推荐房间推断主播身份。旧页的 `nextRoomInfo` 实测可能属于其他主播，不可用于恢复原主播的直播间或播放源。
- 当前直播页仍有效时直接匿名解析并播放，不依赖主播资料卡查询。
- 旧场次结束后，使用已保存的主播 ID 查询网页资料卡，再读取它返回的当前直播间。新房间必须再次核对主播身份。
- 只有主播资料卡明确报告未开播，才更新为未开播。请求受限、超时、身份矛盾、字段缺失均保留未知状态。
- 已结束的旧页面可能不再提供主播 ID。旧本地记录没有身份且页面无法恢复时，提示重新导入直播链接，不承诺修复所有历史地址。
- 已解析出主播 ID 的复制/分享链接带上 `host_id`，避免分享出去的链接在结束后再次丢失身份。

本地关注和历史新增可选 `xiaohongshuHostId` 字段，旧记录无需预先迁移。关注场次更新时保留最早关注时间、特别关注及标签；同一主播的重复关注合并标签引用。历史按主播更新入口并保留最新访问时间。

轮询首次补全主播身份时，即使房间号不变，也会保存到历史；状态仍未知时只保留可信身份，不用未知房间回滚已知当前入口。重复相同的轮询不会重复写历史。首次识别身份和跨场次变化后，关注图标按主播及当前房间重新计算。

小红书状态轮询采用 90 秒组合超时预算，涵盖旧页、首次桌面签名初始化和新页验证；保留在途互斥及切房 generation 检查。其他平台仍使用原有 8 秒预算。原先 8 秒会丢弃约 18 秒才能返回的冷启动签名结果，下一轮又重新初始化，无法推进恢复。

## 网页资料卡

只读目标固定为 `GET https://edith.xiaohongshu.com/api/sns/web/v1/user/hover_card`，使用 `target_user_id` 查询主播，读取 `data.basic_info.live`，兼容网页转换后的 `basicInfo.live`。资料卡提供的当前房间号仍需经直播页确认。

资料卡签名和 H5 直播间签名使用不同的网页上下文，不把资料卡请求拼入 H5 房间路径。网页会话负责签名和 JSON，视频继续由原生播放器播放。

Cookie 保持可选。它可增强受限的资料卡查询，不能成为有效直播链接匿名播放的前置条件。HTTP 200 不等于业务成功：资料卡的 `success=false`、`code=-101` 表示登录信息不可用，不能视为主播下播，也不能触发无休止重试。
