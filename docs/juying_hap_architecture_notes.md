# 聚映 HAP：可借鉴的整体架构

本文基于 `聚映_1.1.0.hap` 的静态拆包与 Ark 字节码反汇编整理，仅作为架构参考，不包含对原包源码或二进制的复制。

## 1. 模块边界

包内大致分为四层：

```text
platform_*  平台适配：房间、播放地址、清晰度、弹幕、登录
     ↓
core        统一模型、接口、数据库、网络、备份
     ↓
entry       页面、路由、生命周期、账号和关注业务
     ↓
common / player / danmaku
            UI 基础组件、播放器、弹幕渲染和后台会话
```

核心接口包括：

- `ILiveSite`：平台统一能力
- `ILivePlayer`：播放控制和状态
- `IDanmakuClient`：弹幕连接和消息

平台服务只负责注册和调度平台实现，上层页面消费统一后的房间模型。这样新增平台时，不需要修改播放器和大部分页面。

## 2. 平台适配建议

建议在现有项目中把平台能力拆成独立适配器，每个平台至少提供：

```text
search / categories / recommend
roomDetail / playQualities / playUrls
checkLiveStatus / createDanmakuClient
```

适配器内部可以有多种数据源，但输出必须先归一化：房间 ID、标题、封面、主播、在线状态、播放地址和请求头都使用统一模型。

## 3. 这个包的工程化亮点

- 关系数据库有迁移链、事务和失败回滚。
- 收藏、历史、标签、WebDAV 配置分表，并有常用索引。
- 备份支持新旧格式、预览、合并、导入和应用后校验。
- 页面、播放器、弹幕、投屏、后台播放分别管理生命周期。
- 通过 `ResponsiveUtil` 统一处理手机、平板、横屏和折叠屏。

## 4. 推荐借鉴顺序

1. 统一平台接口和数据模型。
2. 播放器 Surface 生命周期。
3. 弹幕独立渲染引擎。
4. 数据库迁移与备份验证。
5. 折叠屏和宽屏布局策略。

## 5. 边界和风险

HAP 中的 ArkTS 已经编译为 `modules.abc`，原生库也是作者自己的定制构建。后续实现应基于公开的 HarmonyOS / mpv 能力独立编写，不直接复制原包代码、补丁或二进制。
