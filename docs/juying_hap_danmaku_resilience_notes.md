# 聚映 HAP：弹幕、网络和容错设计

## 1. Canvas 弹幕引擎

它没有把每条弹幕都做成独立 UI 节点，而是由 `DanmakuEngine` 在 Canvas 上统一绘制，并维护：

- 滚动、顶部、底部三种轨道。
- 轨道占用和防重叠。
- 活跃弹幕、开始时间、持续时间和速度。
- 最大数量限制，默认约 200 条。
- 字体缓存、Emoji 分段测量和重排。
- 画布尺寸变化后的在途弹幕缩放。
- 屏蔽词、正则匹配和统一白色模式。

## 2. 重复弹幕合并

重复内容可以合并成一条，并维护 `mergeCount`，显示为类似：

```text
内容 × 3
```

这个操作发生在进入渲染队列前，可以明显减少高峰期弹幕数量。

## 3. 延迟渲染队列

如果 Canvas 还没有尺寸或上下文，弹幕会先进入 `pendingDanmaku`，待画布准备好后再批量刷新，而不是直接丢弃消息。

这对页面切换、画中画进入、折叠屏展开都很有用。

## 4. WebSocket 通用能力

网络层有独立的 WebSocket 客户端，包含：

- 连接、断开和释放。
- 心跳。
- 自动重连。
- 重连计数。
- 取消重连。

平台弹幕客户端在此基础上处理各自的协议，不把断线逻辑散落在页面里。

## 5. 关注状态监控

`FollowLiveMonitor` 负责关注主播的开播检查，并具备：

- 启动、暂停、恢复和停止轮询。
- 应用前后台切换时同步轮询状态。
- 批量更新房间开播状态。
- 批量通知监听者。
- 等待数据库准备完成后再开始工作。

这种设计能避免每个页面各自开定时器，也能减少重复请求。

## 6. URL 和播放地址处理

`LiveUrlResolver` 会先提取候选 URL，再判断是否为已知直播域名，支持粘贴分享文案、短链和带标点的文本。平台适配器随后负责解析房间号和真正播放地址。

建议把这部分做成纯函数，并为以下情况写测试：

- 纯 URL。
- 带文字的分享文案。
- 短链。
- URL 末尾的中文标点。
- 非直播域名。
- 空字符串和恶意输入。
